Use credit to decide where to look and what to change. The capabilities are in
`scripts/procontract_credit.py`; this text is guidance and can be replaced.

Read a record's ledger before reading its transcript. Under one fixed measure it shows which
segments acquired cases, which lost them, which changed the artifact without moving the measure,
and which judged an unchanged artifact again, each with its cost and the harness and action that
produced it. Compare what the last state holds with what the best state held. A measure that every
state passes can assign nothing: treat that as a defect of the measure, not as success.

The ledger says where value moved. It does not say why. Before proposing a change, state the one
input you believe caused a segment's result, and the alternative. Then measure it: continue the
same recorded state with and without that input, on several tasks, and continue some states twice
unchanged to learn how much two identical continuations differ. An effect inside that noise is
not an effect.

Make each located defect an improvement: its terms state the defect, the segments that show it,
and the criterion a change must meet, before any change exists. Put forward one change at a time
on the incumbent, so that its effect is its own. A bundle cannot be credited.

Keep two sets of states. Work on the first: read its cases, iterate, be wrong cheaply. Leave the
second unread, and ask it only for verdicts on candidates you would adopt. Every verdict spends
some of its distance from you; do not query it to tune.

After an adoption, read the ledgers of later work under the new version. If the segments the
change was meant to improve did not improve, say so and withdraw; the defect returns to the
backlog and the previous version serves again.

Apply the same reading to your own improvements. Which of them were defeated, which were adopted
and held, what each cost: that is the improver's ledger, and a change to how you improve is a
change like any other.
